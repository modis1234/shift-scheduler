# 내 일정 문장 명령 — 기간 삭제·색 지정 리뷰

대상: `qitem-20261020042357-25f5d393f7d8b678` (`feature/nl-delete-color` 미커밋 작업 트리, `holidays.ts` 제외)

## Findings

### HIGH — 제목 안의 삭제·색상 문자열을 명령 절로 잘못 떼어 내 실제 삭제/변형 등록으로 바꾼다

- 근거: `web-client/src/lib/manager-pattern-language.ts:15-21,31-44`
- `TARGET_COLOR`, `ALL_COLOR`, `DELETE`가 문장 내 위치나 토큰 끝 경계 없이 전체 문자열에서 치환된다. 따라서 근무 제목 안에 우연히 같은 문자열이 있어도 명령으로 소비된다.
- 재현 1: `parseManagerCommand("2일 일정 삭제방지 점검하고 하루 휴무")`
  - 실제: `deleteExisting: true`, `workTitle: "방지 점검"`
  - 기대: “삭제방지”를 삭제 명령으로 해석하지 않고 원래 제목을 보존하거나 미지원 문장으로 거부해야 한다.
- 재현 2: `parseManagerCommand("2일 빨간색연필 점검하고 하루 휴무")`
  - 실제: `deleteExisting: false`, `workTitle: "연필 점검"`, 근무·휴무 모두 빨간색
  - 기대: “빨간색연필” 내부를 색 지정 절로 소비하지 않고 원래 제목을 보존하거나 거부해야 한다.
- 추가 재현: `2일 근무는 회의하고 하루 휴무`는 제목 `근무는 회의` 대신 제목 `의`, 회색 근무로 해석된다. `회` 뒤의 `색`이 선택 사항이어서 “회의” 앞 글자까지 색으로 소비한다.
- 영향: 첫 재현을 저장하면 사용자가 삭제를 지시하지 않았는데도 선택 기간의 기존 일정 전체가 삭제 대상으로 잡힌다. 미리보기·확인창이 피해 가능성을 낮추지만, “아는 표현만 정확히 떼고 남는 말은 거부”한다는 결정적 파서 계약을 위반하며 데이터 삭제 명령을 오인한다.
- 수정 방향: 삭제/색 절을 임의 부분 문자열 치환으로 찾지 말고, 문장 시작·쉼표·접속어·종결어로 경계가 확인되는 완전한 절만 소비한다. 특히 `삭제|제거`와 색상어 뒤에 허용된 접속/종결 표현이 실제로 끝까지 이어지는지 확인해야 한다.

### MEDIUM — `다시`가 오늘 기준 접두어로 제거되지만 오늘 불일치 검사는 받지 않는다

- 근거: `web-client/src/lib/manager-pattern-language.ts:23,45`, `web-client/src/lib/manager-pattern.ts:49-52`, `docs/planning/main-navigation.md:601`
- `PREFIX`는 문장 시작의 `다시`를 제거해 정상 명령으로 받아들이지만, 입력 검증 정규식은 `오늘부터|오늘 기준`만 검사한다.
- 재현: `startDate=2030-01-02`, `referenceDate=2030-01-01`, `patternText="다시 2일 근무 하루 휴무"`
  - `parseManagerCommand()`는 정상 규칙을 반환한다.
  - 오늘 불일치 정규식은 이 문장에 `false`여서 API 입력이 그대로 통과한다.
- 영향: 문서가 `다시`를 `오늘부터`와 같은 표현으로 정의했는데도 오늘이 아닌 선택 날짜에 등록·삭제할 수 있다. 날짜 의도가 달라지는 실제 계약 불일치다.
- 수정 방향: 오늘 기준 표현 판정을 하나의 공용 함수/정규식으로 만들고 접두어 제거와 입력 검증에서 동일하게 사용한다.

## 확인된 정상 범위

- `해당일에 일정을 삭제해줘`는 삭제 전용 명령으로 해석된다.
- 사용자 결합 예시는 삭제+2일 근무/1일 휴무+휴무 빨강으로 해석된다.
- SQL 삭제 조건은 `store_id`와 선택한 시작일~종료일의 포함 범위로 제한된다.
- batch는 store 행 잠금 뒤 현재 이벤트를 다시 읽어 digest를 비교하고, DELETE와 INSERT를 같은 트랜잭션에서 수행한다.
- `근무 일정을 삭제해줘`, `빨간색으로 삭제해줘`는 거부된다.
