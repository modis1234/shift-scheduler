# 로그인 기획서

상태: v0.2 결정 확정(2026-10-16). 로그인 방식은 카카오 로그인. 구현 지시 전. 결정 내용은 끝의 '결정 사항' 절.

## 변경 이력

| 버전 | 날짜 | 내용 |
|---|---|---|
| v0.1 | 2026-10-15 | 아이디(이메일)·비밀번호 로그인. 결정 5건 확정 |
| v0.2 | 2026-10-16 | 사용자 결정으로 인증 방식을 카카오 로그인으로 변경(v0.1 결정 2 대체). 비밀번호·잠김·scrypt·비밀번호 분실 정책을 삭제하고, 운영자 등록을 초대 링크 방식으로 바꿈. 새 결정 4건 확정(모두 추천안) |

v0.1 결정 중 유지: 계정 1개 = 매장 1곳 = 관리자 1명, 운영자가 계정 생성(셀프 가입 없음), 직원 계정 제외, 서버 JSON 파일 저장(DB는 나중에), 세션 2시간·14일.

## 1. 목적

- **외부 공개 전 차단**: 지금은 주소만 알면 누구나 `POST /api/schedule`(요청당 CPU 최대 100초)를 쓸 수 있다. 등록된 매장 관리자만 화면과 API를 쓰게 한다.
- **비밀번호 없이**: 매장 관리자가 이미 쓰는 카카오 계정으로 로그인한다. 우리는 비밀번호를 받지도 저장하지도 않는다.
- **나중을 막지 않기**: 계정에 `매장` 개념을 처음부터 둔다.
- 범위 밖: 근무표 저장, 직원용 화면, 결제, 셀프 가입, 카카오 외 로그인.

## 2. 사용자와 권한

| 사용자 | 하는 일 | 권한 |
|---|---|---|
| 매장 관리자 | 카카오로 로그인해 근무표를 만든다 | 화면 전체, `/api/schedule` |
| 운영 담당자(우리 팀) | 매장을 등록하고 초대 링크를 만든다. 관리자 교체·계정 삭제 | 서버 관리 스크립트(화면 없음) |
| 등록되지 않은 카카오 사용자 | 카카오 로그인은 되지만 우리 서비스는 못 쓴다 | '등록되지 않은 계정' 안내만 |
| 로그인하지 않은 방문자 | 로그인 화면만 본다 | 그 외 모든 페이지·API 거부 |

- 매장 1곳에 카카오 계정 1개가 연결된다. 연결 키는 카카오 **회원번호**(`/v2/user/me`의 `id`, 문자열로 저장). 이메일은 비즈 앱 심사가 필요할 수 있어 키로 쓰지 않는다.
- 화면 안의 권한 구분은 없다.

## 3. 사용자 흐름

```
[운영 담당자] 매장 등록 + 초대 링크 발급 ──(카톡·문자로 전달)──▶ 매장 관리자

초대 링크(/login?invite=코드) ─▶ 로그인 화면 "OO매장 초대" ─[카카오로 시작하기]─▶ 카카오 로그인·동의
   ─▶ 콜백 ─ 초대 유효 ─▶ 회원번호를 매장에 연결, 초대 사용 처리 ─▶ 메인(/)
            └ 초대 만료·사용됨 ─▶ 로그인 화면 오류 "초대 링크를 쓸 수 없음"

다음부터: 첫 방문(/) ─▶ /login?next=/ ─[카카오로 시작하기]─▶ 카카오 ─▶ 콜백
   ─ 회원번호가 매장에 연결됨 ─▶ next(/)
   ─ 연결 안 됨 ─▶ 로그인 화면 "등록되지 않은 카카오 계정"
   ─ 동의 취소(access_denied) ─▶ 로그인 화면 "로그인을 취소했습니다"
   ─ 카카오 오류·state 불일치 ─▶ 로그인 화면 "로그인하지 못했습니다"

메인 헤더 [로그아웃] ─결과가 있으면 확인─▶ 세션 삭제 + 카카오 로그아웃 ─▶ /login "로그아웃했습니다."
세션 만료 ─다음 요청이 401─▶ 입력 보관 ─▶ /login "다시 로그인해 주세요" ─▶ 카카오 ─▶ 메인, 입력 복원
```

1. **초대(첫 로그인)**: 운영 담당자가 스크립트로 매장을 등록하면 1회용 초대 링크가 나온다(유효 7일). 관리자가 링크로 카카오 로그인을 마치면 그 카카오 회원번호가 매장에 연결되고 초대는 사용 처리된다. 이미 다른 매장에 연결된 카카오 계정이면 연결하지 않고 오류를 보인다(계정 1 = 매장 1).
2. **이후 로그인**: [카카오로 시작하기] → 카카오(이미 카카오에 로그인돼 있으면 동의 화면 없이 바로 돌아옴) → 콜백에서 회원번호로 매장을 찾는다.
3. **콜백 처리**: `state` 확인 → 인가 코드로 토큰 교환 → `/v2/user/me`로 회원번호 조회 → 카카오 토큰은 **즉시 버린다**(이후 카카오 API를 쓰지 않음) → 우리 세션 쿠키 발급.
4. **`next`**: 같은 사이트 경로(`/`로 시작, `//` 아님)만 허용, 아니면 `/`. 카카오 왕복 동안 `state` 쿠키에 함께 보관한다. 이미 로그인한 상태로 `/login`에 오면 바로 `/`.
5. **로그아웃**: 헤더 [로그아웃]. 화면에 결과 근무표가 있으면 먼저 확인한다(저장 기능이 없어 근무표가 사라짐). 우리 세션을 지운 뒤 카카오 로그아웃(`kauth.kakao.com/oauth/logout`)을 거쳐 `/login`으로 돌아온다(결정 사항 2). 공용 매장 PC에서 다음 사람이 이전 관리자로 들어가지 않게 하기 위함이다.
6. **세션 만료**: [근무표 만들기]가 401을 받으면 입력(JSON 텍스트)을 이 브라우저의 `sessionStorage`에 보관하고 로그인 화면으로 보낸다. 다시 로그인하면 복원하고 지운다. 결과 근무표는 보관하지 않는다. 카카오 왕복도 같은 탭에서 일어나므로 `sessionStorage`가 유지된다.
7. **관리자 교체·카카오 계정 분실**: 운영 담당자가 그 매장의 새 초대 링크를 발급한다. 새 계정이 연결되면 이전 연결은 끊긴다.
8. **비밀번호 분실**: 우리 쪽 비밀번호가 없다. 카카오 계정 문제는 카카오에서 해결한다.

## 4. 화면

UI 가이드(`docs/design/ui-guide.md`) 토큰과 컴포넌트를 쓴다. 새로 필요한 것은 카카오 로그인 버튼 하나다.

### 4.1 로그인 (`/login`)

```
            교대근무 스케줄러
     근무 조건을 넣으면 근무표를 만들어 드립니다.
┌ 로그인 ───────────────────────────────┐
│ [안내/오류 상자 — 있을 때만]              │
│ (초대일 때) OO매장 관리자로 초대받았습니다.  │
│ [ 💬 카카오로 시작하기                 ]  │
│ □ 로그인 상태 유지 (개인 기기에서만)        │
│ 등록된 매장 관리자만 쓸 수 있습니다.         │
│ 처음이라면 받은 초대 링크로 들어와 주세요.   │
└──────────────────────────────────────┘
```

- 가운데 카드 하나, 폭 최대 400px, 모바일 좌우 16px. 헤더 없음.
- **카카오 버튼**은 카카오 디자인 가이드를 따른다(노랑 `#FEE500`, 글자 검정 85%, 말풍선 심볼, 문구 "카카오로 시작하기" 또는 "카카오 로그인"). UI 가이드의 '주 버튼은 파랑' 규칙의 예외이며, 이 화면에는 다른 주 버튼이 없다. 높이 40px, 카드 폭 가득. 다크 모드에서도 같은 노랑. 버튼은 `<a>`(서버 라우트로 이동)이며 누른 뒤 "카카오로 이동하는 중…" + 비활성.
- 초대 링크로 왔을 때만 초대 문구 한 줄(매장 이름 표시). 초대 코드가 유효하지 않으면 매장 이름 대신 오류 상자.

| 상태 | 화면 |
|---|---|
| 정상 | 위 배치 |
| 이동 중 | 버튼 "카카오로 이동하는 중…", 비활성 |
| 등록되지 않은 계정 | `.alert-warning`: "이 카카오 계정은 등록되어 있지 않습니다. 매장 등록은 운영 담당자에게 문의해 주세요. 받은 초대 링크가 있다면 그 링크로 다시 들어와 주세요." |
| 초대 링크 사용 불가 | `.alert-warning`: "초대 링크가 만료되었거나 이미 사용되었습니다. 운영 담당자에게 새 링크를 요청해 주세요." |
| 이미 다른 매장에 연결된 계정 | `.alert-warning`: "이 카카오 계정은 이미 다른 매장에 연결되어 있습니다. 다른 카카오 계정으로 로그인하거나 운영 담당자에게 문의해 주세요." |
| 동의 취소 | `.alert-info`: "카카오 로그인을 취소했습니다. 다시 하려면 [카카오로 시작하기]를 눌러 주세요." |
| 카카오 오류·state 불일치·토큰 교환 실패 | `.alert-danger` `role="alert"`: "카카오 로그인을 마치지 못했습니다. 잠시 뒤 다시 시도해 주세요." |
| 너무 잦은 요청(IP) | `.alert-warning`: "로그인 시도가 너무 많습니다. 잠시 뒤 다시 시도해 주세요." |
| 세션 만료로 옴 | `.alert-info`: "로그인 시간이 지나 다시 로그인해 주세요. 입력하던 근무 조건은 이 브라우저에 보관했습니다." |
| 로그아웃 후 | `.alert-info`: "로그아웃했습니다." |

- 오류는 콜백이 `/login?error=<코드>`로 돌려보내고 화면이 코드를 문구로 바꾼다. 카카오의 원문 오류(`error_description`)는 화면에 보이지 않는다(서버 로그만).

### 4.2 메인 헤더 변경 (`/`)

- 헤더 오른쪽 근무 기간 뒤에 `매장 이름`(muted 12px) + [로그아웃] `.btn-secondary` 작은 버튼. 모바일에서는 근무 기간 아래 줄.
- 로그아웃 확인(결과가 있을 때만): "로그아웃하면 화면의 근무표가 사라집니다. 로그아웃할까요?" [취소] [로그아웃]. 네이티브 `<dialog>`, 포커스는 [취소].
- 입력 복원 직후 1 근무 조건 입력 위에 `.alert-info` 한 번: "로그인 전에 입력하던 근무 조건을 불러왔습니다."

## 5. 정책

| 항목 | 규칙 |
|---|---|
| 계정 키 | 카카오 회원번호(숫자 → 문자열). 매장 1곳 ↔ 회원번호 1개 |
| 동의 항목 | 요청하지 않음(회원번호는 동의 없이 받음). 결정 사항 3 |
| 초대 링크 | 128비트 이상 무작위 코드, 1회용, 유효 7일. 파일에는 코드 해시만 저장. 운영 담당자가 매장마다 발급, 새로 발급하면 이전 미사용 링크는 무효 |
| 계정 파일 | 서버의 JSON 파일(매장 id, 매장 이름, 카카오 회원번호, 초대 코드 해시·만료, 연결 시각). Docker 배포 시 이미지 밖 볼륨에 둔다. 경로는 환경변수. 쓰기(초대 사용)는 임시 파일에 쓴 뒤 이름 바꾸기로 원자적으로, 한 프로세스 전제 |
| state | 로그인 시작마다 무작위 `state`를 만들어 짧은 수명(10분) `HttpOnly` 쿠키에 넣고 콜백에서 비교. 다르면 거부. `next`·'로그인 상태 유지'·초대 코드도 이 쿠키에 함께 둔다 |
| redirect URI | 환경변수 하나로 고정(`/auth/kakao/callback`). 요청 헤더로 만들지 않는다. 카카오 콘솔에 로컬·배포 주소를 등록 |
| 카카오 토큰 | 회원번호 조회 후 저장하지 않고 버린다. 우리 세션과 카카오 토큰 수명은 무관 |
| 세션 | 서명된 쿠키(`HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`). 서명 키는 환경변수 |
| 세션 유지 | v0.1 그대로. 기본: 브라우저를 닫으면 끝, 마지막 사용 후 2시간 지나면 만료. '로그인 상태 유지': 14일. 둘 다 로그인부터 최대 14일. 카카오 세션이 살아 있으면 재로그인은 버튼 한 번이라 부담이 작다 |
| 로그아웃 | 우리 세션 쿠키 삭제 + 카카오 계정 로그아웃(결정 사항 2). 모든 기기 일괄 로그아웃은 서명 키 교체(운영 작업) |
| IP 제한 | 같은 IP에서 1분에 20회 넘는 로그인 시작·콜백 요청 → 429 |
| 보호 범위 | `/login`, `/auth/kakao/*`, 정적 파일을 뺀 모든 페이지와 API. API는 리다이렉트 대신 401 JSON |
| 엔진 사용량 | 기존 동시 실행 제한(`ENGINE_MAX_CONCURRENCY`) 유지. 계정별 제한은 범위 밖 |
| 삭제 | v0.1의 아이디·비밀번호 규칙, scrypt, 실패 횟수 잠김, 비밀번호 분실 안내는 없앴다(카카오가 인증을 맡음) |

환경변수: `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`, `KAKAO_REDIRECT_URI`, `SESSION_SECRET`, `ACCOUNTS_FILE`, `KAKAO_LOGOUT_REDIRECT_URI`.

## 6. 보안·개인정보 최소 요구

- 외부 공개는 HTTPS에서만(`Secure` 쿠키). 로컬 개발은 `http://localhost:3000` 예외.
- 시크릿(`KAKAO_CLIENT_SECRET`, `SESSION_SECRET`)은 환경변수로만. 코드·이미지·로그에 넣지 않는다. 인가 코드·카카오 토큰·쿠키 값도 로그에 남기지 않는다. 로그인 로그에는 시각, IP, 결과, 회원번호만.
- 콜백은 `state` 불일치, `error` 파라미터, 토큰 교환 실패를 모두 로그인 실패로 처리하고 세션을 만들지 않는다.
- 개인정보: 저장하는 것은 카카오 회원번호와 매장 이름뿐(동의 항목을 요청하지 않음). 회원번호도 개인을 식별하는 정보이므로 공개 전에 개인정보 처리방침에 수집 항목(회원번호), 목적(로그인), 보관 기간(매장 계정 삭제 시 즉시 삭제)을 적는다. 근무표의 직원 이름은 지금처럼 서버에 저장하지 않는다.
- `/login`, `/auth/kakao/*` 응답에 `Cache-Control: no-store`.

## 7. 카카오 앱 설정 체크리스트 (사용자가 developers.kakao.com에서)

콘솔 메뉴 이름은 바뀔 수 있다. 막히면 dev-be에게 화면을 공유한다.

1. 내 애플리케이션 → 애플리케이션 추가(앱 이름 "교대근무 스케줄러", 아이콘). 이 이름과 아이콘이 카카오 로그인 화면에 보인다.
2. 앱 키 → **REST API 키** 확인 → 배포 환경변수 `KAKAO_REST_API_KEY`.
3. REST API 키의 **Client Secret** 확인(기본 활성) → 코드 값을 `KAKAO_CLIENT_SECRET`에. 활성 상태 유지.
4. 카카오 로그인 → **사용 설정 ON**(OFF면 KOE004 오류).
5. **Redirect URI 등록**: `http://localhost:3000/auth/kakao/callback`, `https://<배포 도메인>/auth/kakao/callback`. 다르면 KOE006 오류.
6. **로그아웃 리다이렉트 URI 등록**: `http://localhost:3000/login`, `https://<배포 도메인>/login`.
7. **플랫폼 → Web 사이트 도메인**: `http://localhost:3000`, `https://<배포 도메인>`.
8. **동의 항목**: 아무것도 설정하지 않는다.
9. 배포 도메인이 정해지면 5~7에 추가한다(지금 배포 호스트 미정).
10. 키 4개(REST API 키, Client Secret, 세션 서명 키, 계정 파일 경로)를 배포 담당(dev-deploy)에게 안전한 경로로 전달. 채팅·이슈에 붙이지 않는다.

## 8. 완료 기준

1. 로그인하지 않은 상태에서 `/`는 `/login?next=/`로, `POST /api/schedule`은 401로 막힌다(curl).
2. 초대 링크로 카카오 로그인하면 그 카카오 계정이 매장에 연결되고 메인으로 간다. 같은 링크를 다시 쓰면 '사용 불가'가 나온다.
3. 연결된 카카오 계정은 [카카오로 시작하기]로 들어가 근무표를 만들 수 있다.
4. 연결되지 않은 카카오 계정, 동의 취소, `state`가 다른 콜백은 세션이 생기지 않고 각 문구가 나온다.
5. '로그인 상태 유지'를 안 하면 브라우저를 다시 열었을 때 로그인 화면이 나오고, 하면 그대로 들어간다.
6. 입력 중 세션이 만료된 뒤 [근무표 만들기] → 카카오 로그인 → 입력이 그대로 복원된다.
7. 결과가 있을 때 로그아웃하면 확인 대화상자가 뜨고, 로그아웃하면 카카오 계정도 로그아웃되어, 다시 [카카오로 시작하기]를 누르면 카카오 로그인 화면이 나온다.
8. 쿠키에 `HttpOnly`·`Secure`·`SameSite=Lax`가 붙고, 계정 파일·로그에 카카오 토큰과 초대 코드 원문이 없다.
9. 로그인 화면이 키보드만으로 동작하고, 라이트·다크 모두 대비 기준을 지킨다.
10. 운영 담당자가 문서화된 명령으로 매장 등록·초대 링크 발급·관리자 교체·삭제를 할 수 있다.
