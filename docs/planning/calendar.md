# 근무 캘린더 기획서

상태: v0.1 결정 확정(2026-10-16). 1·2단계 구현됨. 3단계(직원 보기 PWA 베타) 계약·완료 기준 확정(2026-10-19, 7-3절). 규모는 기획자 **추정**.

## 1. 목적과 사용자

- **관리자**: 만든 근무표를 날짜 중심으로 한눈에 본다(이날 누가 어느 근무조인지, 휴가자는 누구인지). 지금 결과 그리드는 '직원 × 날짜'라 사람 중심이다.
- **직원**: 내 근무 날짜·시간과 같은 날 함께 일하는 동료를 휴대폰으로 확인한다.
- 범위 밖: 직원의 근무 교환·휴가 신청, 알림(카톡·문자 발송), 여러 매장 합쳐 보기.

## 2. 의존 관계 (먼저 있어야 하는 것)

```
[1단계] 관리자 캘린더 보기 + 인쇄 ─── 선행 없음 (지금 화면의 결과로 바로 가능)
[2단계] 근무표 저장 + 확정·게시 ──── 선행: 저장소(DB 또는 파일), 로그인(구현 중)
[3단계] 직원이 보기 ──────────────── 선행: 2단계(게시된 근무표) + 직원 접근 방식(결정 2)
[4단계] 관리자 수정 ──────────────── 선행: 2단계 + 수정 후 재검증(결정 3)
```

- 지금은 결과가 브라우저 화면에만 있어 새로고침하면 사라진다. **직원이 보려면 저장과 '게시' 상태가 반드시 먼저 필요**하다. 저장 없이 직원에게 전달하는 방법은 인쇄·이미지뿐이다.
- 로그인은 계정 1 = 매장 1 = 관리자 1이고 직원 계정은 제외했다(로그인 결정 4). 직원 카카오 로그인을 고르면 그 결정을 다시 열어야 한다.
- 엔진 출력 `schedules[{date, shift, assigned_employees[{employee_id, name, …}]}]` + 입력의 `shift_definitions`(이름·시작·종료·시간), `approved_leaves`로 캘린더를 모두 그릴 수 있다. 엔진 변경은 필요 없다.

## 3. 보기 방식

| 보기 | 대상 | 구성 | 기기 |
|---|---|---|---|
| 월 | 관리자 기본 | 7열 달력. 날짜 칸에 근무조별 줄 "오픈 3명"(근무조 색 + 이름). 휴가자가 있으면 "휴가 1명". 칸을 누르면 일 보기 | 데스크톱 우선, 모바일은 근무조 점(●)과 인원만 |
| 주 | 관리자·직원 | 행 = 근무조(시간 표시), 열 = 7일, 칸 안에 직원 이름 | 데스크톱. 모바일은 일 목록으로 대체 |
| 일 | 관리자·직원 | 근무조별 블록: "오픈 08:00–16:00 · 김민수, 이서연, 박지훈". 휴가자 목록 | 모바일 기본 |
| 내 근무(목록) | 직원 | 날짜순 목록 "11월 3일 (화) 오픈 08:00–16:00 · 함께: 이서연, 박지훈" | **모바일 우선** |

- **필터**: 직원(선택 상자, 한 명 고르면 그 직원 근무만 강조), 근무조(체크박스). '내 근무만'은 직원 보기(3단계)에서만 의미가 있다.
- **오늘 표시**: 오늘 날짜 칸에 accent 테두리 + "오늘" 글자. 근무 기간 밖이면 기간 첫날로 연다.
- **휴가**: UI 가이드의 `leave` 색 + "휴가" 글자.
- **인원 부족**: 엔진이 만든 근무표(SUCCESS)는 필요 인원을 항상 채우므로 1~3단계에는 나오지 않는다. 4단계(수정)에서 필요 인원보다 적으면 칸에 warning 색 + "1명 부족".
- **색**: 근무조 색·주말 글자색(일 = danger, 토 = accent)·용어는 UI 가이드를 그대로 쓴다. 색만으로 구분하지 않고 근무조 이름을 항상 같이 쓴다.
- **모바일 우선 여부**: 관리자 화면은 지금처럼 데스크톱 우선, 직원 화면(3단계)은 모바일 우선.

## 4. 화면

### 4.1 결과 영역의 보기 전환 (1단계)

- ③ 결과 카드 머리 오른쪽에 보기 전환 `[직원별 표] [달력]`(`aria-pressed` 보조 버튼 두 개, UI 가이드 '탭 대신 보조 버튼' 규칙). 기본은 지금의 직원별 표.
- 달력 보기 위에 `[월] [주] [일]` + `‹ 이전` `다음 ›` + 필터 + `[인쇄]`(보조 버튼).
- **인쇄**: 브라우저 인쇄(`window.print()` + 인쇄용 CSS). A4 가로, 월 보기 한 장, 헤더에 매장 이름·근무 기간. PDF 저장도 같은 대화상자에서 된다. 이미지(PNG) 내보내기는 새 의존성이 필요해 제외.

| 상태 | 화면 |
|---|---|
| 정상 | 위 구성 |
| 근무표 없음(아직 안 만듦) | 결과 영역 빈 상태 그대로: "근무 조건을 입력하고 [근무표 만들기]를 누르면 여기에 근무표가 나옵니다." |
| 만드는 중 | 기존 로딩 그대로 |
| 조건 불충족·입력 오류 | 기존 결과 안내 그대로, 보기 전환 숨김 |
| 필터 결과 없음 | "선택한 조건에 맞는 근무가 없습니다. 필터를 바꿔 보세요." |

### 4.2 근무표 목록·게시 (2단계)

- 메인 위쪽 "저장된 근무표" 목록: 근무 기간, 상태 배지(`작성 중` / `게시됨`), 만든 날짜. 행을 누르면 결과 + 달력.
- 결과 영역에 `[저장]`, 저장된 근무표에 `[게시하기]` / `[게시 취소]`. 게시 확인: "게시하면 직원이 이 근무표를 볼 수 있습니다. 게시할까요?"
- 같은 근무 기간에는 게시된 근무표가 하나만 있다. 새로 게시하면 이전 것은 `게시 취소됨`.

| 상태 | 문구 |
|---|---|
| 목록 로딩 | 표 자리에 스켈레톤 3줄, `aria-busy` |
| 목록 비어 있음 | 점선 카드: "저장된 근무표가 없습니다. 근무표를 만든 뒤 [저장]을 눌러 주세요." |
| 저장 실패 | `.alert-danger`: "근무표를 저장하지 못했습니다. 잠시 뒤 다시 시도해 주세요. 화면의 근무표는 그대로 있습니다." |

### 4.3 직원 보기 (3단계, 결정 2-b 기준)

- 주소 `/s/<공유 코드>`, 로그인 없음, 읽기 전용, 모바일 우선. 위에서부터: 매장 이름 · 근무 기간 → "내 이름 선택"(선택 상자, 이 기기에 기억) → **내 근무 목록**(기본) / 일 / 주 전환.
- 같은 날 동료는 이름만 보인다. 직원 id·시급·고용 형태·숙련 등 다른 입력값은 보이지 않는다.

| 상태 | 문구 |
|---|---|
| 게시된 근무표 없음 | "아직 게시된 근무표가 없습니다. 매장 관리자에게 문의해 주세요." |
| 링크가 잘못됨·중지됨 | "링크를 열 수 없습니다. 매장 관리자에게 새 링크를 요청해 주세요." (어느 쪽인지 구분하지 않음) |
| 로딩 | 목록 스켈레톤 |
| 내 근무 없음 | "이 기간에는 배정된 근무가 없습니다." |

## 5. 정책

| 항목 | 규칙 |
|---|---|
| 데이터 원천 | 캘린더는 근무표 결과 + 입력(근무조 정의, 휴가)만으로 그린다. 별도 계산 없음 |
| 저장 단위 | 근무표 1개 = 입력 + 결과 + 상태(작성 중/게시됨/게시 취소됨) + 만든 시각. 매장에 속함 |
| 게시 | 게시된 근무표만 직원에게 보인다. 게시 후 수정하려면 게시 취소 → 수정 → 다시 게시 |
| 공유 링크 | 매장마다 1개, 128비트 이상 무작위, 관리자가 [링크 새로 만들기]로 바로 무효화. 검색 엔진 차단(`noindex`), `Cache-Control: no-store` |
| 직원에게 보이는 정보 | 이름, 근무 날짜·근무조·시간, 같은 날 동료 이름, 휴가 여부. 그 외 입력값(시급, 고용 형태, 숙련, 근로시간 상한, 가용 시간)은 보내지 않는다(서버에서 걸러서 응답) |
| 수정(4단계) | 수정 결과는 엔진의 재검증(`validate`, 계산 없이 규칙만 확인)을 통과하거나, 위반을 화면에 보여 준 뒤 관리자가 알고 저장한다(결정 3) |
| 날짜·시각 | 매장 현지 시각. 자정을 넘는 근무조(마감 16:00–24:00)는 시작한 날에 표시 |

## 6. 개인정보

- 1단계(인쇄): 서버에 새로 저장하는 것 없음. 인쇄물 관리는 매장 책임.
- 2단계(저장): **직원 이름과 근무 기록이 처음으로 서버에 저장**된다. 개인정보 처리방침에 항목(직원 이름, 근무 일정, 휴가일, 시급·고용 형태 등 입력값), 보관 기간(예: 근무 기간 종료 후 3년, 근로기준법 서류 보존 기간 참고 — 확인 필요), 삭제 방법을 적는다. 수집 주체는 매장(관리자)이고 우리는 처리 위탁 관계가 된다.
- 3단계 공유 링크: 링크를 가진 사람은 매장 직원 전원의 근무 일정을 본다. 매장 벽에 붙이는 근무표와 같은 수준으로 보고, 다른 정보는 내보내지 않는다. 링크 유출 시 관리자가 즉시 새로 만든다.
- 3단계 직원 카카오 로그인(결정 2-c): 직원 회원번호 수집과 직원-계정 연결 관리가 추가된다.

## 7. 완료 기준 (1단계)

1. 근무표를 만든 뒤 [달력]을 누르면 월 보기가 나오고, 날짜마다 근무조별 인원과 휴가 인원이 근무조 색·글자로 보인다.
2. 월 → 일 보기로 들어가면 근무조별 시간과 직원 이름이 보인다. 주 보기는 근무조 × 7일.
3. 직원 필터로 한 명을 고르면 그 직원 근무만 강조되고, 근무조 필터가 동작한다.
4. 오늘 날짜가 표시되고, 주말 글자색·휴가 표시가 UI 가이드와 같다.
5. [인쇄]로 A4 가로 한 장에 월 보기가 나오고(버튼·필터 숨김) PDF로 저장된다.
6. [직원별 표]로 돌아오면 지금 결과 그리드가 그대로다.
7. 키보드로 보기 전환·날짜 이동이 되고, 날짜 칸에 `aria-label`("11월 3일 화요일, 오픈 3명, 마감 2명, 휴가 1명")이 있다. 라이트·다크 대비 기준 충족.
8. 모바일(≤640px)에서 페이지 가로 스크롤이 없고, 월 보기는 근무조 점과 인원만 보인다.

2~4단계 완료 기준은 결정 후 추가한다.

## 7-3. 완료 기준 (3단계: 직원 보기, PWA 베타)

범위: 4.3절 화면 + 5·6절 정책. 웹앱(PWA) 설치까지. 네이티브 앱·서비스워커·오프라인 캐시는 제외(no-store와 충돌). 새 의존성 없음, 엔진·기존 관리자 API 변경 없음.

### 계약

**저장** — Postgres(Supabase, `DATABASE_URL`)에 표 하나. 저장소 이전(결정 7)의 마이그레이션에 같이 넣는다(001 또는 002).

```sql
CREATE TABLE share_links (
  store_id <stores.id와 같은 타입> PRIMARY KEY REFERENCES stores(id) ON DELETE CASCADE,
  code text NOT NULL UNIQUE,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

- 코드: `randomBytes(16)`(128비트) → base64url 22자. 매장당 1행. 새로 만들면 같은 행을 덮어써 이전 코드는 그 즉시 404.
- 코드는 평문 저장. 근거: 관리자가 언제든 [복사]해야 하고, 같은 DB에 이미 더 민감한 입력값(시급 등)이 있다. 초대 코드처럼 해시로 저장하면 다시 보여 줄 수 없다.
- 형식(`^[A-Za-z0-9_-]{22}$`)이 아니면 DB 조회 없이 404.

**관리자 API** (로그인 필요, 기존 `sessionStore` 사용, `Cache-Control: no-store`)

| 요청 | 응답 |
|---|---|
| `GET /api/share-link` | 200 `{ code: string \| null, createdAt: string \| null }` |
| `POST /api/share-link` | 201 `{ code, createdAt }` — 없으면 만들고, 있으면 새 코드로 바꾼다 |

화면 주소는 프런트가 `${location.origin}/s/${code}`로 만든다.

**직원 API** (로그인 없음) `GET /api/s/<code>`

- 코드가 없거나 바뀌었거나 형식이 틀리면 모두 404 `{ error: "링크를 열 수 없습니다." }`. 어느 쪽인지 구분하지 않는다.
- 200 응답. **아래 필드만** 서버에서 새 객체로 만들어 보낸다. 저장된 input·result를 걸러 보내지 말고 아래 모양으로 새로 만든다:

```ts
{
  storeName: string,
  periods: Array<{                       // 게시됨(published)만, startDate 오름차순. 없으면 []
    startDate: string, endDate: string,  // YYYY-MM-DD
    shifts: Array<{ name: string, start: string, end: string }>, // shift_definitions 순서, hours>0만(엔진처럼 Off 제외). start/end "HH:MM"
    employees: string[],                 // 이 근무표 입력의 직원 이름(이름 선택 상자용), 가나다순
    days: Array<{ date: string, shift: string, names: string[] }>, // 엔진 schedules에서 이름만
    leaves: Array<{ date: string, name: string }>, // approved_leaves 중 기간 안 날짜만
  }>
}
```

- 나가지 않는 것(예시): 직원 id, 시급, 고용 형태, 숙련, 근로시간 상한·가용 시간, `assignment_reason`, `rotation_offset`, 공정성 점수·인건비·경고, 근무표 id, 작성 중·게시 취소된 근무표.

**헤더** — `/s/*` 화면과 `/api/s/*` 응답 모두: `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`(주소에 코드가 있음). 화면에는 `<meta name="robots" content="noindex, nofollow">`도 넣는다.

**베타 토글** — 환경변수 `STAFF_SHARE_BETA=1`일 때만 켠다(그 외 값·없음 = 꺼짐).

- 꺼짐: `/s/*` 404(Next `notFound()`), `/api/s/*`·`/api/share-link` 404, 관리자 화면의 공유 링크 영역 숨김(`page.tsx`가 env를 읽어 prop으로 넘긴다). `share_links` 행은 지우지 않으므로 다시 켜면 같은 링크가 열린다.

**middleware.ts** — `isPublic`에 `/s/`로 시작하는 경로와 `/api/s/`로 시작하는 경로를 추가한다. `manifest.webmanifest`·`.png`·`.svg`는 지금 matcher에서 이미 빠져 있으므로 바꿀 것 없음(확인만).

**PWA**

- `public/manifest.webmanifest`: `name` "근무표 (베타)", `short_name` "근무표", `display: "standalone"`, `scope: "/s/"`, 아이콘 `docs/design/app-icon/app-icon-512.png`·`-128.png`를 `public/`에 복사해 쓰고, `app-icon.svg`도 `"sizes": "any"`로 함께 넣는다. **`start_url`은 넣지 않는다.** 그러면 설치한 페이지(`/s/<코드>`)가 시작 주소가 된다.
- `<link rel="manifest">`, `apple-touch-icon`, `theme-color`는 `/s/*` 화면에서만 넣는다. 관리자 화면은 설치 대상이 아니다.

**여러 게시본** — 기간이 다른 게시본이 여러 개면 화면 위쪽에 기간 선택(보조 버튼 또는 선택 상자)을 둔다. 처음 고르는 기간: 오늘(기기 날짜)이 들어 있는 기간 → 없으면 가장 가까운 앞으로의 기간 → 없으면 가장 최근에 끝난 기간. 기간이 겹치면 합치지 않고 따로 보여 준다. 게시본이 하나면 선택 영역을 숨긴다.

**이름 선택** — `localStorage`에 이름을 기억한다(키 `shift-scheduler:staff-name:<코드>`). 저장된 이름이 고른 기간의 `employees`에 없으면 선택하지 않은 상태로 연다. 같은 이름이 둘이면 구분할 수 없다. 관리자가 입력에서 이름을 다르게 적어야 한다(베타 한계, 화면에는 안내하지 않음).

**관리자 화면 링크 영역** — "저장된 근무표" 카드 아래쪽에 "직원 공유 링크" 줄을 둔다.

- 링크가 있을 때: 읽기 전용 입력칸(주소) + `[복사]` + `[링크 새로 만들기]`(보조 버튼). 안내 "게시된 근무표만 직원에게 보입니다."
- 링크가 없을 때: `[링크 만들기]`만.
- 새로 만들기 확인: "새 링크를 만들면 지금 링크는 바로 열리지 않습니다. 새로 만들까요?"
- 복사가 끝나면 `aria-live`로 "복사했습니다". 실패하면 입력칸을 선택해 둔 채 "복사하지 못했습니다. 주소를 직접 복사해 주세요."

### 확인 항목 (be·fe·qa)

1. `STAFF_SHARE_BETA` 없음: `/s/아무거나`, `/api/s/아무거나`, `/api/share-link` 모두 404이고, 관리자 화면에 링크 영역이 없다.
2. 켬, 로그아웃 상태: `/s/<코드>`가 로그인으로 보내지 않고 열린다. `/api/share-link`는 401.
3. [링크 만들기] → 22자 코드. [링크 새로 만들기] 뒤 이전 코드의 `/s/`·`/api/s/`는 404이고, 화면은 "링크를 열 수 없습니다…"다.
4. `/api/s/<코드>` 응답 JSON의 키가 위 계약과 정확히 같다. 입력에 시급·고용 형태 등이 있어도 응답 본문에 그 값이 없다(본문 문자열 검색으로 확인).
5. 작성 중·게시 취소된 근무표는 나오지 않는다. 게시를 취소하면 다음 요청부터 사라진다. 게시본이 없으면 "아직 게시된 근무표가 없습니다…"가 보인다.
6. 다른 매장의 코드로는 다른 매장 근무표만 보인다(두 매장 교차 확인).
7. 응답 헤더에 `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`가 있고, 화면 HTML에 robots meta가 있다.
8. 휴대폰 폭(360px)에서 가로 스크롤 없음. 이름 선택 → 내 근무 목록(4.3절 문구·형식) → 일·주 전환이 된다. 새로고침하면 이름이 기억되어 있다. 내 근무가 없으면 "이 기간에는 배정된 근무가 없습니다."
9. 게시본 둘(기간 다름): 오늘이 든 기간이 먼저 열리고 다른 기간으로 바꿀 수 있다.
10. 화면에 "베타" 배지가 보인다. Android Chrome에서 "홈 화면에 추가"를 하면 앱 아이콘으로 설치되고, 설치한 앱은 같은 `/s/<코드>`로 열린다(manifest 오류 없음: DevTools Application 탭).
11. 키보드로 이름 선택·보기 전환이 되고, 라이트·다크 대비 기준을 충족한다(UI 가이드 v2).
12. 기존 관리자 기능(로그인, 근무표 만들기, 저장·게시, 달력)이 그대로다.
